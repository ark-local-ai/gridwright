## 三、架构决策备忘（详见 8-变化原因）
- **后端**：Node 22 + TS + Fastify + 内置 `node:sqlite`（零编译，Windows 友好）。
- **编排**：先自写状态机，留 `plannerLLM` 接入点，按需演进（不提前上 LangGraph）。
- **进度推送**：SSE（单向持续推送 + replay 缓存）。
- **LLM**：openai 兼容 fetch adapter，零依赖，DeepSeek/OpenAI/Ollama 通吃。
- **Office 交付**：pptxgenjs / exceljs / docx（全 JS，零原生编译），按需求关键词选类型，产出可编辑真实文件。
- **模型路由**：router 按渠道成功率选优，统计写 SQLite；坏渠道自动降权。
- **验收/重试**：verifier 对交付文件做真实校验（存在/非空/zip），失败限次重试。
- **工作空间**：`GET /api/workspace` 真扫 `frontend/public/workspace/`，按类型/大小/时间列出；前端工作空间页调它展示 + 下载（与任务交付联动）。
- **对话流式**：`POST /api/chat` SSE 逐 token 推送；配 key 走真实模型 `chatStream`，无 key 走内置回复逐字流式降级。
- **自动化**：`scheduler/jobs.ts` 本地 Cron（jobs/job_logs 表），30s 轮询匹配「每天 HH:MM / every:N 分钟」到点调 runTask 并记日志；同分钟防重。
- **模型渠道**：DB 持久化（channels 表，env 引导种子），CRUD + 验活（GET /models）+ 设默认；router/planner 直接消费 DB 渠道。
- **连接器**：`GET /api/connectors` 真实状态——渠道计数 + Ollama 探测（GET /api/tags），未接入的如实标未接入（不假在线）。
- **场景库**：`GET /api/scenarios`（`data/scenarios.ts` 6 场景），首页/提示词库共用；前端 `listScenarios` 拉取（mock 仅离线降级）。
